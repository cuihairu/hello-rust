# Closures and the Fn Trait Family

A closure is an "anonymous function + captured environment": it is not a function pointer but an anonymous type generated by the compiler, which implements one or more of `Fn`, `FnMut`, and `FnOnce` depending on what it captures. The only difference between the three traits is the method receiver — `FnOnce::call_once(self)`, `FnMut::call_mut(&mut self)`, `Fn::call(&self)` — that is, **how much authority a single call consumes**. This page covers capture inference, `move`, and typical uses of `FnOnce` in the standard library.

## Capture mode is decided by usage

How a closure captures the environment is determined by **how the closure body uses it**: read-only borrows a reference, mutation borrows a mutable reference, and moving takes it by value. Conversely, the closure body determines which traits it can implement:

```rust
// 三个 trait 的接收者不同：&self / &mut self / self
fn apply_fn<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 { f(x) }
fn apply_fnmut<F: FnMut(i32) -> i32>(mut f: F, x: i32) -> i32 { f(x) }
fn apply_fnonce<F: FnOnce(i32) -> i32>(f: F, x: i32) -> i32 { f(x) }

fn main() {
    // 只读捕获：同时实现 Fn、FnMut、FnOnce
    let n = 10;
    let add_n = |x| x + n;
    println!("Fn:      {}", apply_fn(add_n, 5));
    println!("FnMut:   {}", apply_fnmut(add_n, 5));
    println!("FnOnce:  {}", apply_fnonce(add_n, 5));

    // 可变捕获：只实现 FnMut 和 FnOnce
    let mut count = 0;
    let mut bump = |x| { count += 1; x + count };
    println!("FnMut:   {}", apply_fnmut(&mut bump, 5));
    println!("FnOnce:  {}", apply_fnonce(&mut bump, 5));

    // 移动捕获（消耗环境变量）：只实现 FnOnce
    let s = String::from("moved");
    let consume = move |_| s.len() as i32;
    println!("FnOnce:  {}", apply_fnonce(consume, 0));
}
```

Actual run output:

```text
Fn:      15
FnMut:   15
FnOnce:  15
FnMut:   6
FnOnce:  7
FnOnce:  5
```

The capabilities are nested: a closure that implements `Fn` necessarily also works as `FnMut` and `FnOnce`; capturing a mutable environment drops it out of `Fn`; consuming the environment by value leaves only `FnOnce`. So APIs that take closures should **relax to `FnOnce` whenever possible** — it is the most caller-friendly.

### Calling `FnMut` requires a mutable binding

`FnMut` calls go through `&mut self`, so the closure binding itself must be `mut` — no exception after a `move` handoff:

```rust
// FnMut 需要可变接收者：普通调用也得保证 mut
fn main() {
    let mut count = 0;
    let mut bump = |x| { count += 1; x + count };
    let f = bump;          // move：bump 变成不可变绑定
    f(1);
    f(2);                  // f 是不可变绑定，调用 FnMut 会失败
}
```

Actual run output (excerpt, the warning portion omitted):

```text
error[E0596]: cannot borrow `f` as mutable, as it is not declared as mutable
 --> fnmut_binding.rs:5:9
  |
4 |     let mut bump = |x| { count += 1; x + count };
  |                          ----- calling `f` requires mutable borrow of `count`
5 |     let f = bump;          // move：bump 变成不可变绑定
  |         ^ not mutable
6 |     f(1);
  |     - cannot borrow as mutable
7 |     f(2);                  // f 是不可变绑定，调用 FnMut 会失败
  |     - cannot borrow as mutable
```

## `move` closures: taking ownership

`move` forces the closure to capture all variables it uses by value, without borrowing the environment:

```rust
fn main() {
    let s = String::from("data");
    let own = move || println!("owned: {s}");   // move：按值拿走 s
    own();
}
```

Actual run output:

```text
owned: data
```

The most typical scenario is **when the closure outlives the environment**: returning closures, or throwing closures into threads. Returning a closure without `move` fails to compile outright (E0373, see the [`impl Trait`](./impl-trait) page); `std::thread::spawn` constrains its argument to `FnOnce() + Send + 'static`, where `move` is even more mandatory.

## Closures as arguments and return values

In argument position, use `impl Fn(i32) -> i32` (equivalent to generics + bounds, see [Zero-cost abstraction](./zero-cost-abstraction)); in return position, `impl Fn` is the standard form — both go through static dispatch. Only when you need "a group of closures with the same signature packed into one collection" do you switch to `Box<dyn Fn>`, paying the cost of dynamic dispatch for the flexibility (comparison in [Trait objects](./trait-objects)).

## `OnceCell::get_or_init`: a typical `FnOnce` scenario

The signature of `OnceCell::get_or_init` is `get_or_init<F>(&self, f: F) -> &T where F: FnOnce() -> T` — the initialization closure is **called at most once**, so constraining to the loosest `FnOnce` is sufficient:

```rust
use std::cell::OnceCell;

fn main() {
    let cell = OnceCell::new();

    let v1 = cell.get_or_init(|| {
        println!("initializing... (expensive)");
        42
    });
    println!("first call -> {v1}");

    let v2 = cell.get_or_init(|| {
        println!("initializing... (should not happen)");
        99
    });
    println!("second call -> {v2}");
    assert_eq!(v1, v2);
}
```

Actual run output:

```text
initializing... (expensive)
first call -> 42
second call -> 42
```

The second closure was never executed — `should not happen` never appeared. This kind of API that "may only be called once" (`unwrap_or_else`, `map_or_else`, and so on) all relaxes the bound to `FnOnce` — a direct application of the three traits' hierarchy.
